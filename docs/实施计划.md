## TASK_STATE 管理提示（运行时完整注入内容）

> 对长期、需交接或可能经历 compact 的任务，Better Compact 在选定唯一项目后直接创建/静默维护该项目的 `TASK_STATE.md`，记录目标、已确认边界、已排除项、当前状态和下一步；项目不唯一时才询问用户选择一级目录。
>
> 关键状态变化后更新，后续继续任务前先读取该文件，作为防止 compact 丢失任务状态的持久状态源，若冲突以可验证事实为准，并及时修正TASK_STATE。
>
> 不在其中记录密钥、令牌、密码或隐私信息。

## 实施目标

将现有 Windows Continuity Hooks 改造为 Better Compact。它只在 compact 或 resume 造成恢复边界时，向 Codex 一次性注入继续任务所需的最小上下文；不在每次编辑前重复注入规则。

## 已确认产品行为

- Windows 为当前唯一支持平台；不实现 Linux。
- workspace 就是 Codex 当前工作目录；不向上推断或扫描父目录。
- 用户级全局 Skill 安装在 `C:\Users\<user>\.agents\skills\better-compact\`；当前 workspace 的运行目录为 `<workspace>\.agents\skills\better-compact\`。
- workspace 目录包含运行时脚本、配置、提示词、Recovery、日志、安装元数据和 workspace-local 卸载脚本；项目语义状态仅保留在对应项目根目录的 `TASK_STATE.md`。
- 初次安装仍由发布包的 `windows\Install.ps1` 手动完成。安装器创建默认双 ON 配置、注册一个全局 Skill，并合并用户级 `hooks.json`；用户仍须在 Codex 信任 Hook。
- Skill 会在符合条件的长期任务中自动选择：唯一项目后无确认初始化 Better Compact，并创建或静默维护项目 `TASK_STATE.md`；项目不唯一时只询问一级目录。
- 不存在 `task-state clear`、全局开关、自动 `.gitignore` 修改、旧版自动迁移、完整聊天/Prompt/transcript/raw patch 保存、自动选择不唯一项目或自动任务总结。
- Core OFF 时 TASK_STATE 配置保持原值，但 Hook 读取配置后立即退出，不注入、不记录、不写日志；Core 再 ON 后恢复行为。
- 配置不存在或 JSON 损坏时，按 Core ON、TASK_STATE ON 处理。
- 已存在的本地目录仅在安装元数据确认它是 Better Compact 时才升级。升级替换运行脚本和提示词，保留配置、Recovery 和日志；未知或损坏目录中止，不覆盖。
- 旧版 `C:\Users\<user>\.codex\continuity-hooks\<hash>` 不迁移；用户先手动卸载旧版再全新安装。

用户级 `C:\Users\<user>\.codex\hooks.json` 不存放 Better Compact 状态；它只保留三个指向该 workspace 本地 `runtime\continuity.ps1` 的 Hook 定义。为使备份在本地目录卸载后仍可用，`hooks.json` 的安全备份与它保存在同一目录，而不是工具目录内。

## 配置与控制器

`config\workspace.json` 是当前 workspace 的唯一配置来源：

```json
{
  "schemaVersion": 1,
  "coreEnabled": true,
  "taskStateEnabled": true
}
```

`runtime\Control.ps1` 只读写此文件。Skill 按当前工作目录调用它；不安装、不卸载、不修改 Hook 定义。

`status` 必须显示：

```text
Core
TASK_STATE
Workspace
Tool directory
Active project
Recovery Card directory
```

## Hook 生命周期与注入顺序

安装器只注册以下三项，不再注册 `PreToolUse`：

| Event | Matcher | 职责 |
| --- | --- | --- |
| `PostToolUse` | `^apply_patch$` | 仅在成功编辑后更新 active project 和 Recovery Card。 |
| `PreCompact` | `^(manual|auto)$` | 为 active project 的 Recovery Card 记录 compact 时间。 |
| `SessionStart` | `^(compact|resume)$` | 仅在恢复边界重新注入上下文。 |

Core ON 的 `SessionStart` 恢复顺序固定为：

```text
Codex 已有的根 AGENTS.md
  → Better Compact 额外补入的 active project 的 AGENTS.md（存在时）
  → prompts\task-state.md（TASK_STATE = ON）
  → active project 的 TASK_STATE.md（TASK_STATE = ON 且存在时）
  → active project 的 Recovery Card（存在时）
```

- 不注入 README。
- 不在 `startup` 注入。
- 不在 `PreToolUse` 注入、记录 active project 或写审计日志。
- 项目识别保持现有约定：workspace 一级子目录为项目，`docs` 和 `.codex` 为共享目录，不建立 Recovery Card。
- 项目 `AGENTS.md` 和 `TASK_STATE.md` 各自最多注入 5,000 字符；超出时附加 `[truncated]`。工具自带的 `prompts\task-state.md` 为完整短文本。Recovery Card 保存并注入最多 12 个去重后的项目相对路径，以短文本卡片呈现，不注入原始 JSON。

## 文件改动与职责

| 文件 | 改动职责 |
| --- | --- |
| `windows\Install.ps1` | 注册一个用户级全局 Skill，并向当前 workspace 的 `.agents\skills\better-compact` 安装运行文件；初始化双 ON 配置；安全合并三个 Hook；处理已安装目录升级或拒绝未知目录。 |
| `windows\continuity.ps1` | 改为只处理 `PostToolUse`、`PreCompact`、`SessionStart`；读取本地配置；实现新的恢复注入顺序；移除 README 与 `PreToolUse` 分支。 |
| `windows\Control.ps1`（新增） | 处理 Core/TASK_STATE 开关和 status；缺失或损坏配置按双 ON 返回。 |
| `windows\Uninstall.ps1` | 作为发布源，安装后复制到 workspace-local `runtime`；只清理该 workspace 的三个 Hook 和该目录。 |
| `windows\Watch-ContinuityDiagnostics.ps1` | 从新的 workspace-local `logs` 目录读取诊断日志。 |
| `windows\Test-ContinuityHooks.ps1` | 重写/扩展为 Hook、Controller、安装器和卸载的临时隔离测试。 |
| `skill\SKILL.md`（新增） | 用户级全局 Skill 源；自动选择长期任务、定位唯一项目、无确认初始化并静默维护 TASK_STATE。 |
| `prompts\task-state.md`（新增） | 保存 TASK_STATE 管理提示；只有唯一项目已被选定时才创建或维护文件。 |
| `README.md` | 更新安装、信任、目录、命令、默认状态、关闭/卸载和 `.gitignore` 说明。 |

## 实施步骤

1. 建立发布源中的 Skill、提示词和 Controller；定义 workspace-local 路径与配置读写公共函数。
2. 改造 Hook dispatcher：删除 `PreToolUse`，保留成功编辑记录与 compact 标记，将恢复注入限制为 `compact|resume`。
3. 改造安装器：注册用户级全局 Skill，并只复制运行文件到本地目录；写安装元数据和双 ON 配置；将 `hooks.json` 的四项注册降为三项。
4. 改造 workspace-local 卸载器和监视器，使其只读取/清理新的目录与本 workspace 的 Hook 注册。
5. 扩展隔离测试并逐项运行；最后执行一次真实 Codex 的手动 compact/resume 验收。
6. 更新 README，使用户能从安装到信任、开关、诊断和卸载完整操作。

## 验收标准

- `PostToolUse` 成功编辑才创建或更新 Recovery Card；失败编辑不改变 active project 或 Recovery Card。
- `PreCompact` 仅标记已有 active Recovery Card。
- `SessionStart(source=compact|resume)` 按固定顺序注入；`startup` 和每次编辑均不注入。
- Core OFF 时三类 Hook 无注入、无 Recovery/active/log 写入；重新 ON 后恢复。
- TASK_STATE OFF 时只跳过管理提示和项目 `TASK_STATE.md`，Recovery Card 仍可恢复；Core OFF 时两者都不生效。
- 配置缺失或损坏按双 ON；`status` 输出六个确认字段。
- 安装器保留 `hooks.json` 合并/取消/备份安全性；升级保留状态、未知目录不覆盖；卸载只影响当前 workspace 的三个 Hook 与本地目录。
- README 不承诺自动加入 `.gitignore`，也不包含旧版自动迁移。

## 非目标

- Linux、GUI、多 profile、全局控制器、自动选择不唯一项目、Hook 自动改写 TASK_STATE、自动读取详细 docs、自动 `.gitignore`、自动迁移旧安装、Plugin 化分发、保存完整会话内容。
